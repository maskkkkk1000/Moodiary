# Domain behavior and data contracts

All event times are milliseconds since the Unix epoch. Day-based records use ISO local dates, with no implicit UTC conversion. Entry grouping, filtering, achievements and linked goal calculation use the timezone explicitly supplied by the caller. A timezone change can therefore move historical entries between local dates; reconcile automatic goal completions after a timezone change. Manual completion dates stay fixed.

Statistics use each entry's historical mood snapshot. Editing a mood definition does not reinterpret past scores. The overall mean and distribution weight each entry equally. Daily trend points average entries on that local date; there is no invented value for a missing day. Weekday means weight recorded local days equally. Activity frequency reports entry counts and distinct day counts separately. Same-entry associations compare entries containing an activity with other recorded entries in the selected range.

Next-day associations include adjacent pairs only when both the source date and following date have entries and are inside the selected inclusive date range. One source date contributes one following-day mean, regardless of how many entries or activity selections it contains. Source dates containing the activity form the exposed group; other observed source dates form the baseline group. Missing days are omitted, never treated as a neutral score. Calendar arithmetic uses `LocalDate.plusDays(1)` and is correct across DST, leap days, month/year boundaries and changing UTC offsets. Date changes, edits and deletions are reflected by recomputation from source data.

Confidence is a sample-size heuristic, not statistical certainty or a confidence interval: fewer than 5 observations is insufficient, 5–14 low, 15–29 medium, and 30 or more high. Comparisons use the smaller group's count so a large exposed group cannot disguise an inadequate baseline. Association differences remain absent when either comparison group is empty. Observational differences cannot establish causation. Pair exploration covers the 24 most frequent activities, reporting the 20 most common pairs; this deliberately bounds large-dataset work and must be disclosed when displaying combination insights. Baselines for pairs are entries without that complete pair.

Each goal can complete at most once per local date. Daily and weekday goals require one completion per scheduled date. Weekly goals count distinct completed dates within Monday–Sunday weeks, with targets of 1–7. A partial first or last week retains the configured weekly target. Daily/weekday streaks count consecutive scheduled opportunities, so a non-scheduled day cannot break a streak. Weekly streaks count weeks meeting target. An incomplete current day/current week is pending and does not yet break a streak. Completion rate includes elapsed opportunities through today (and the current weekly target), capped at 100%. Ended goals have a fixed historical streak. Archived goals retain historical eligibility. Automatic reconciliation derives the desired `(goalId,date)` set from all remaining qualifying entries; retain existing manual rows, remove obsolete automatic rows and add missing desired rows transactionally. Manual rows outside an edited schedule remain in history but no longer contribute to the revised metrics.

Backup version 1 contains metadata, database JSON, preferences and managed photos. Photo database paths and callback/map keys are safe basenames; ZIP paths are `photos/<basename>`. The metadata photo manifest stores SHA-256 values keyed by basename. Every referenced photo must appear once, and no unreferenced archive photos are accepted. Restore must decode and validate completely before replacing active state. `BackupCodec` has bounded uncompressed per-file, total-size and file-count limits; larger archives fail clearly. Limits can be lowered by Android callers to fit available memory. ZIP traversal, unexpected files, shared photo paths, duplicate archive paths, duplicate entity IDs, broken relationships, malformed ISO dates, invalid settings and unsupported format versions are rejected. Backup settings intentionally contain no PIN hash or biometric secret; Android restore must preserve device security and reacquire any document-tree permissions on the current device. Checksums detect corruption, not malicious authorship. Backup archives are not encrypted.

JSON export preserves all structured journal entities. CSV uses RFC 4180 quoting and CRLF row endings. The Activities column is a JSON string array within one CSV cell, so activity names containing commas, pipes, quotes or Unicode stay unambiguous. Formula-like free-text cells are prefixed with an apostrophe to reduce spreadsheet injection; use JSON for byte-exact note round trips.
